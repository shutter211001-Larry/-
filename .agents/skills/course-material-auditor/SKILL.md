# 課程教材專案稽核員

對整個教學專案做可追溯的盤點。先了解目錄與專案規範，再抽取教材結構、素材與可能過時的陳述；用檔案路徑、段落標題和查證來源支持發現。以繁體中文回報，聚焦會妨礙教學、跟做或發布的問題。

## 工作流程

1. **確認專案範圍**：讀取根目錄說明、適用的 `AGENTS.md`、教材目錄、技能目錄及建置／預覽入口。以檔案清單辨識文件、網頁、腳本、樣式和媒體素材；不要只憑 README 的描述判斷實際內容。
2. **確認課程主軸並建立課程地圖**：先用一句話寫出學員真正要學會的能力，再列出章節順序、每章主要概念與實作、明示時長及主要產物。檢查工具示範、案例與提示詞是否服務這條主軸，避免示範工具反過來變成課程主角。對簡報只需比較教學重點與順序，不要求投影片逐字複製講義。
3. **檢查文字與素材引用**：對每份 Markdown，以該檔所在位置解析相對連結與圖片路徑；對 HTML 檢查本地 `src`、`href`、CSS／JS 引用及存在的素材檔。標示失效連結、尚未替換的佔位文字、錯置的相對路徑與 README／實際檔案不符之處。不要把外部網址無法離線存取直接判成壞連結。
4. **比對跨媒體與專案規範**：若教材同時有講義和投影片，抽查並比對章節名稱、核心概念、示範、實作與圖片，不要求字句完全一致。檢查專案規範是否已過期、彼此矛盾，或與教材現況不符（例如規範宣稱移除佔位圖，但文件仍留有佔位）。
5. **標記時效性與可驗證性**：把模型版本、排行榜、價格、免費額度、平台功能、介面位置、下載／安裝指令等列為易變資訊。若使用者需要事實查核，優先查產品官方文件、價格頁、公告或原始專案頁，記下查核日期並在報告中附來源連結。非官方來源只用於補充；找不到可靠來源時明確標示「未能確認」，不可推測或照抄課程中的斷言。
6. **依重要性整理報告**：先列會讓學員無法完成、導致錯誤決策或令發布內容失真的項目，再列次要一致性與文案問題。每一項附檔案路徑、標題／行號（可取得時）、觀察證據、影響和建議處理方式。分開陳述已確認問題、待查證事項與改善建議。

## 專案型教材的檢查項目

- **可跟做性**：前置帳號、軟體、權限、材料和步驟是否齊全；操作描述是否依賴未附的畫面截圖、範例檔或已移動的介面。
- **素材完整性**：圖片是否存在、相對路徑是否以實際文件位置解析、佔位是否還留在講義或投影片中。
- **時數可信度**：只加總文件明示的時長，核對單元、休息、轉場與成果發表；不要假裝可從字數精確推得講授時間。
- **學習順序**：一個新概念後是否有相應練習或檢查點；區分短暫實作緩衝與正式休息，不因一般原則要求硬塞休息。
- **指令層次**：若教材教授 Agent 工作流，檢查是否清楚區分「使用者如何引導 Agent」、「Skill／AGENTS.md 保存什麼」與「Agent 寫給下游模型的提示詞」。若只展示最終提示詞，學員可能把過程誤認為黑箱或咒語。
- **範例從屬關係**：確認 Kling、ComfyUI、商品短片等範例被標示為驗證工作流的方法，而不是取代課程主題。每個範例都應能指出它正在示範工作流中的哪一步。
- **高風險主張**：警惕「永遠免費」「絕對安全」「一定支援」「最強／最新」等無來源或不必要的絕對說法，特別是涉及費用、帳號、模型相容性或檔案安全時。
- **專案自己的規則**：遵守現行 `AGENTS.md` 對受眾、風格、素材、課程節奏及跨媒體同步的要求；若這些規則已經過時或互相衝突，把矛盾列為發現，不要默默選一邊。

## 輸出格式

```markdown
# 教材專案稽核報告

## 範圍
- 已檢閱：...
- 未能檢閱／限制：...

## 優先處理
1. **[高／中／低] 問題標題** — `path/to/file`（章節／行號）
   - 發現：...
   - 影響：...
   - 建議：...

## 待查證的時效性內容
- 主張、所在位置、查核結果與來源連結；若未查，清楚標為尚未查證。

## 完整性與一致性
- 連結、素材、文件與簡報、規範與現況的主要發現。

## 建議處理順序
1. ...
```

若沒有發現某一類問題，簡短註明已檢查且未發現，不要製造問題來填滿報告。使用者只要求稽核時回報發現，不要自行改寫整套教材；若使用者也授權修正，先處理高優先級、可逆的修正，並遵守專案對講義與簡報同步的要求。
