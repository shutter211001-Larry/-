# 教材專案設計準則與自我修正記錄 (AGENTS)

此文件為我們「閉環學習機制」的知識沉澱與規則庫。當使用者針對教材內容提出回饋、糾正或風格調整時，我們將紀錄在此處，確保後續章節不再犯相同錯誤，達到自我學習與優化的目的。

## 全局風格指南
- **受眾視角**：以「初學者」為對象，使用淺顯易懂的語言。
- **結構化排版**：善用標題、條列式與粗體字來強調重點。
- **實作導向**：每個觀念盡量搭配具體情境或範例。
- **自我審查標準**：
  1. 名詞解釋是否精準無誤？
  2. 內容是否會過於艱澀？
  3. 步驟是否連貫、可操作？
  4. **(NEW)** 在介紹新觀念前，是否已拋出痛點或生動案例（如 ChatGPT 災難）來建立「為什麼要學」的記憶點？

## 自我修正紀錄庫 (Feedback Log)
*(當收到使用者回饋後，將在下方持續新增修正事項與新規則)*

- **[2026-07-30] 初始化**：建立閉環機制，確保留下修改軌跡。
- **[2026-07-30] 痛點與案例導向教學**：收到回饋，後續在介紹觀念（如閉環、提示詞）前，必須先舉出生動或崩潰的案例（例如「女扮男裝卻變成啤酒肚大叔長胸部」），讓學員深刻理解「為何而學」。
- **[2026-07-30] 對話式 (Chat-like) 敘事**：痛點場景禁止單調的長篇大論，必須採用「對話氣泡」的方式（例如：你一句、AI/老闆回一句，搭配生動的分鏡圖片），創造帶入感與張力。
- **[2026-07-30] 目標受眾與五階段學習流**：
  1. **受眾語言**：全體受眾為「美術設計單位」，教學時必須將技術名詞翻譯為設計師語言（如：將 Agent 比喻為自動批次助理、GitHub 是無極限的 Ctrl+Z、解釋節點式與圖層架構的差異），**且必須附上生動的案例對比 (如時空旅行、打疫苗)**。
  2. **標準結構**：每個章節必須嚴格遵守「**痛點 > 名詞解釋 > 功能 > 示範 > 實作**」的流程，且**「避坑 TIP (新手大坑)」必須統一放在實作區塊**。
  3. **分離式漸進教學法 (True Progressive Learning)**：嚴禁將多個觀念綑綁後再一次性實作，必須採用「教一個觀念 ➔ 進行該觀念的實作 ➔ 再教下個觀念 ➔ 再實作」的交替式節奏。所有的實作必須具備對比性 (例如：`理論 A (Web GPT 差異)` ➔ `實作 A (裸測)` ➔ `理論 B (SKILL 身分)` ➔ `實作 B (見證奇蹟)`)，讓學員深刻體驗工具帶來的反差。

- **[2026-07-30] 術語翻譯與情境化 (Terminology Translation)**：受眾為設計師與行銷人員，在教材與簡報中引入任何技術術語時，必須將其翻譯為直覺理解的「生活化比喻」(例如：YAML Frontmatter ➔ 員工識別證、Git ➔ 時空旅行、KSampler ➔ 靈魂畫師、VAE Decode ➔ 底片沖洗室)。
- **[2026-07-30] 強制雙向同步 (Strict Synchronization)**：每次修改教材底下的任何 Markdown 檔案時，必須強制檢查並同步更新 presentation/index.html 中對應的幻燈片內容 (包含文字、比喻、圖片等)，嚴禁單邊更新。
- **[2026-07-30] 主動式閉環更新 (Autonomous Meta-Rule)**：當解決使用者的問題，或是受到使用者的糾正後，必須「主動」檢討改進方案，並自行更新相關的 SKILL.md 或 AGENTS.md 檔案，確保下次絕對不會再犯同樣的錯誤。
