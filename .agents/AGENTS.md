# 教材專案設計準則與自我修正記錄 (AGENTS)

此文件為我們「閉環學習機制」的知識沉澱與規則庫。當使用者針對教材內容提出回饋、糾正或風格調整時，我們將紀錄在此處，確保後續章節不再犯相同錯誤，達到自我學習與優化的目的。

## 1. 環境設定與工具 (Setup commands)
- **教學環境**：本專案為 Markdown 文本與 HTML 網頁混合架構。
- **Start presentation server**: `npx serve presentation` (用於預覽修改後的幻燈片，可開啟 http://localhost:3000 查看)
- **同步要求**：每次修改 `*.md` 教材內容後，請務必連同 `presentation/index.html` 一併更新，嚴禁單邊修改。
- **依賴工具**：本專案使用 `skills.sh` 引入外部技能（如 `comfyui-prompt-engineer`），請確保遵守技能的標準格式。

## 2. 專案風格與慣例 (Project style)
- **Code Style (Markdown)**：使用標準 GitHub Flavored Markdown。請勿使用 HTML 標籤（除非必要），縮排使用 4 個半形空白，條列式項目符號統一使用 `-` (Hyphen)。
- **受眾視角**：以「初學者 / 美術設計單位」為對象，使用淺顯易懂的語言。
- **術語轉譯**：必須將冰冷的技術名詞翻譯為直覺理解的「生活化比喻」(如：YAML Frontmatter ➔ 員工識別證、Git ➔ 時空旅行、CFG ➔ 靈感發散度)。
- **對話式敘事**：痛點場景禁止單調的長篇大論，必須採用「對話氣泡」的方式（你一句、AI/老闆回一句）創造帶入感。
- **結構化排版**：每個章節嚴格遵守「**痛點 > 名詞解釋 > 功能 > 示範 > 實作**」的標準流程，且「避坑 TIP」統一放在實作區塊。
- **分離式漸進教學法**：嚴禁將多個觀念綑綁一次性實作，必須採用「教一個觀念 ➔ 進行該觀念的實作 ➔ 再教下個觀念」的交替節奏。

## 3. 審核與驗證指南 (Testing instructions)
- **教材自我審查標準**：
  1. 名詞解釋是否精準且口語化？
  2. 內容是否會過於艱澀（有沒有忘記設計師聽不懂程式碼）？
  3. 在介紹新觀念前，是否已拋出痛點或生動案例（如 ChatGPT 災難）來建立記憶點？
- **提示詞驗證**：若需生成生圖提示詞，必須檢查是否已經加入反向提示詞 (Negative Prompts) 來避免六指、肢體變形等問題。

## 4. 非程式碼資產管理 (Non-Code Assets)
- **設計與規格存放**：遵循 agents.md 社群規範，所有非程式碼的專案資產（如：UI/UX 參考圖、品牌視覺指南、角色設定集）應統一放置於 `.agents/references/` 目錄下。
- **Agent 讀取原則**：在執行設計任務前，Agent 應主動去查閱上述目錄中的視覺規範，而非憑空想像。
