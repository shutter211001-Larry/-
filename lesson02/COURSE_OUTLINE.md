## 一、這堂課要教什麼

這堂課不是教學員背一段 Kling 提示詞，而是讓他們看懂：一位導演如何只用高階語言交代創意，再由 Agent 讀取素材、補齊技術細節、產生參考圖與模型提示詞、操作 Kling MCP、追蹤任務、交付成果，最後把有效方法整理成可以重跑的工作流。

課堂以一份真實對話紀錄為主線。學員會看到工作流如何在對話中逐步形成，也會看到 Agent 用錯工具後，使用者如何糾正分工，並把修正寫回工作流。

這次工作流並不是從空白提示詞開始。使用者先把原本在 Comfy 工作流中使用的示範提示詞帶進來，指定為新的視覺描述基準。Agent 的任務是讀懂這段提示詞如何組織景別、主體、動態、焦點、光線與情緒，再依 ChatGPT Image Generation 與 Kling O3 的輸入方式重新表達。

本課的核心流程是：

```text
讀取既有 Comfy 工作流與提示詞
→ Agent 辨認可沿用的創意結構與原模型控制
→ 導演提出新的創意
→ Agent 讀取規則與素材
→ Agent 補齊技術決策
→ Agent 提出參考圖與影片方案
→ 導演核准
→ Agent 呼叫生成工具
→ Agent 追蹤並交付結果
→ 導演驗收與修正
→ 將已驗證的方法保存成 Skill
```

Kling O3、ChatGPT Image Generation、MCP 和提示詞都是流程中的工具。課程主角是「如何引導 Agent 工作」。

## 三、學習成果

課程結束後，學員應能：

1. 用自己的話說明 Agent、生成模型、工作介面、MCP 與 Skill 的分工。
2. 依任務是否需要專案脈絡、工具、多步驟、核准與驗收，判斷一般網頁對話何時足夠、何時需要 Agent。
3. 區分產品／工作介面與語言模型，並用同一份任務、相同輸入與共同評分表做公平比較。
4. 用高階中文交代創意目標、不可改動項目、核准點與驗收方式。
5. 分辨三個層次：導演給 Agent 的指令、工作流保存的規則、Agent 寫給生成模型的提示詞。
6. 看懂 Comfy 工作流中的節點、連線與資料流，知道提示詞只是一項輸入。
7. 說明模型、文字編碼、取樣、潛在資料、VAE、參考控制與輸出節點各自負責什麼。
8. 說明既有 Comfy 提示詞如何成為創意與描述風格的參考，而不是被誤認成 Kling 官方格式。
9. 看懂 Agent 如何把「蹲下抬頭，使用廣角鏡頭」轉成參考圖方案與影片方案。
10. 檢查 Agent 的技術決策是否有來源、是否符合目前模型及工具能力。
11. 在付費生成前確認模型、素材、提示詞、參數、版本數與預期成本。
12. 使用 Kling MCP 完成能力確認、素材提交、生成、任務查詢與結果交付。
13. 根據生成結果指出一個主要偏差，提出下一版只改一個主要變因的修正。
14. 把已驗證的方法保存成 Skill，把單次素材與執行紀錄留在專案中。
15. 將同一套 Agent 工作方法轉移到人物短片、商品影片或其他生成任務。

## 四、學員看到的七章學習線

1. **建立共同語言**：分清楚 Agent、工作介面、影片模型、提示詞與工具。
2. **選擇工作模式**：依任務是否需要專案、工具、多步驟與驗收，判斷一般網頁對話或 Agent 哪一種較合適。
3. **拆學員問題**：用真實案例定位需求、素材、方法、工具或驗收缺口。
4. **先看完整工作流**：先看成果如何完成，再回頭讀原始對話與決策證據。
5. **追查方法來源**：從 Comfy 提示詞與節點辨認文字、素材和參數的責任。
6. **轉譯並完成任務**：製作參考圖、改寫 Kling 輸入、操作 MCP 並驗收 MODEL 成片。
7. **轉移並保存**：把同一方法轉移到商品影片，最後保存成可重跑的 Skill。

### 影片生成模型與 Agent 模型比較活動

影片生成模型先固定創意意圖、素材、片長、畫幅與驗收標準，再依官方文件重寫輸入：Kling 使用主體、動作、場景與攝影語言；Veo 補上構圖、鏡頭、氣氛與聲音；Runway 圖片生成影片時集中描述動作；Seedance 可依時間區段寫敘事與節奏；Wan／ComfyUI 還要把負面提示與節點參數一起記錄。完全相同的字串只作格式相容性測試。

Agent／語言模型使用以下固定題目比較：

比較題目固定為：

```text
請讀取這個 Kling O3 專案的規則、既有紀錄與角色素材，提出一支影片方案。先交付中文意圖摘要、ChatGPT 參考圖提示詞、Kling O3 影片提示詞、素材責任、生成參數與驗收表；不要送出付費生成。
```

## 六、主案例拆解

### 1. 前情提要：示範提示詞來自 Comfy

建立 Kling O3 工作流時，使用者先提供這段提示詞：

```text
Wide shot of a free-spirited young woman running toward the camera through a sun-drenched field, white birds exploding upward all around her like symbols of freedom. Her hair and dress are caught by the wind, captured with crisp focus on her face and light motion blur in the foreground flowers and wings. Vivid colors, bright clear sky, optimistic, uplifting cinematic tone.
```

這段文字是從既有 Comfy 工作流直接帶過來的示範提示詞。它在新工作流中的用途是提供一個已知的描述風格：

1. 先說景別、主體與主要動作。
2. 再說環境中發生的動態。
3. 指定清楚焦點與允許出現動態模糊的位置。
4. 交代色彩、光線與情緒。

課堂必須明確說明：

- 這不是 Kling 官方提示詞範本。
- 這段文字來自 Comfy，不代表原文直接交給 Kling 就一定得到相同結果。
- 可沿用的是創意意圖、視覺描述順序與導演偏好的語氣。
- Agent 仍要依 ChatGPT 參考圖與 Kling O3 影片的不同責任，重新組裝實際輸入。
- 新工作流驗證的是「這次轉譯與執行能否完成目標」，不是替原始 Comfy 提示詞建立跨模型通則。

這個前情讓學員看見一項重要能力：建立工作流不一定從空白開始。Agent 可以讀取既有的成功資產，辨認哪些部分是創意、哪些部分是模型寫法，再把可沿用的內容帶到新的工具鏈。

### 2. 先讓學員看懂 Comfy 裡有哪些東西

ComfyUI 官方將它定義為節點式的生成式 AI 介面與推論引擎。課堂不要求學員從空白建立大型工作流，而是要求他們能沿著節點連線，理解一份既有工作流如何把資料送到下一步。

課堂使用實際 Comfy 工作流辨認以下角色；不同模型的節點名稱可能不同，因此以功能與連線方向為主：

| 工作流角色 | 白話解釋 | 學員要看懂的事 |
| --- | --- | --- |
| 模型載入 | 選擇這次負責生成的模型與相關元件 | 換模型可能同時改變提示詞習慣、節點需求與可用控制方式 |
| 文字編碼 | 把提示詞轉成模型使用的條件資料 | 文字會先經過編碼，不是直接變成像素；編碼器必須與模型架構相容 |
| 正向與負向條件 | 指定希望出現與希望排除的內容 | 它們是取樣時使用的條件，不是整條工作流 |
| 參考圖與控制條件 | 提供姿勢、邊緣、深度、角色或風格等額外依據 | 有些要求已由圖片或控制節點負責，不應全部重複塞進文字 |
| 潛在資料 | 模型運算中的壓縮表示 | 畫面在生成過程中不一定以可直接觀看的像素存在 |
| 取樣 | 模型依條件逐步把雜訊轉成結果 | 種子、步數、引導強度、取樣器、排程與降噪都可能改變結果 |
| VAE 編碼／解碼 | 在像素圖片與潛在資料之間轉換 | 解碼後才得到可以觀看與儲存的圖片；實際模型可能有專用 VAE |
| 輸出 | 預覽或保存圖片、影片 | 工作流成功執行只代表產生檔案，仍需進行內容驗收 |

課堂使用這條簡化資料流：

```text
模型與素材
＋ 提示詞經文字編碼形成的條件
＋ 參考圖或其他控制條件
→ 取樣器在潛在資料中生成結果
→ VAE 或對應解碼器轉成可觀看內容
→ 預覽／保存
```

Comfy 的提示詞因此不能脫離原工作流解讀。要把它搬到 Kling，Agent 至少要先回答：

1. 原本是哪個模型和文字編碼器在解讀這段文字？
2. 原工作流還用了哪些參考圖、ControlNet、LoRA 或其他條件？
3. 哪些構圖、角色、動作或風格其實由節點和參數控制？
4. Kling 的介面能否接受相同控制？若不能，應改由參考圖、文字或後製負責？
5. 原本如何固定種子、參數與版本，讓比較有意義？

本段依 2026 年 10 月 11 日查閱的 [ComfyUI 核心概念](https://docs.comfy.org/essentials/core-concepts/links)、[CLIP Text Encode 節點](https://docs.comfy.org/built-in-nodes/ClipTextEncode)、[KSampler 節點](https://docs.comfy.org/built-in-nodes/KSampler)與 [VAE Decode 節點](https://docs.comfy.org/built-in-nodes/VAEDecode)整理。實際授課仍以當天使用的 Comfy 工作流、模型與節點為準。

### 3. 使用者再提供新的創意核心

主案例中的原始要求是：

> 我想要這個角色風格，讓他蹲下抬頭，鏡頭使用廣角鏡頭看他。

這是一條合格的高階指令，因為它已經交代三件重要的事：

- 角色外觀以附件為依據。
- 表演是蹲下並抬頭。
- 視覺重點是廣角鏡頭。

它沒有指定所有攝影與生成細節。Agent 的工作是先讀參考素材與專案規則，再提出可讓導演判斷的方案，而不是要求導演先學會完整的模型語法。

### 4. Agent 將創意轉成鏡頭方案

Agent 補齊的內容包括：

- 貼近地面的低機位。
- 20mm 廣角的透視感。
- 夜間石板路與舊建築環境。
- 直閃與微弱暖色窗光。
- 臉部保持清楚，邊緣逐漸失焦。
- 頭髮、衣料與金屬飾品的次要動態。
- 攝影機只做一次緩慢前推。
- 以親密、緊張、反叛的電影情緒收束。

這些是 Agent 的提案，不是原始指令中已經存在的事實。導演可以核准、修改或放棄。

### 5. 先分開參考圖與影片的責任

| 階段 | 主要責任 | 本案例 |
| --- | --- | --- |
| 原始角色圖 | 角色身分、臉部、服裝與造型 | 黑色碎髮、針織帽、深灰上衣、寬褲、皮帶與銀飾 |
| ChatGPT 正式參考圖 | 第一幀姿態、鏡位、構圖、場景、光線與色彩 | 蹲姿、低機位、廣角透視、夜間石板路、直閃 |
| Kling O3 影片提示詞 | 動作起點、動作發展、環境反應、攝影機運動、結尾與聲音 | 先低頭、再抬起下巴看向鏡頭；頭髮與銀飾輕微運動；攝影機緩慢前推 |

課堂要讓學員看懂：同一個創意不是複製同一段提示詞到每個工具，而是讓每項輸入負責它最適合控制的資訊。

2026 年 10 月 11 日的實作整理又把 Kling O3 提示詞精鍊成三句。第一句建立鏡頭與事件，並在自然句子中交代圖片 1 的角色責任與圖片 2 的姿態／構圖責任；第二句描述物理反應、清晰焦點、受控模糊及一個主要運鏡；第三句以色彩、光線與二至三個一致的情緒詞收尾。通常控制在 55—100 個英文單字。這是 `sources/KLING_O3_PROMPT_GUIDELINES.md` 保存的專案寫作策略，不是 Kling 官方保證有效的固定語法；換題材或版本後仍要用同素材、同參數與共同驗收表實測。

### 6. 把錯誤修正成規則

案例一開始曾使用 Kling Image O3 生成參考圖。使用者隨後明確更正：

> 圖片是由 ChatGPT 生成。

Agent 接著更新分工：正式參考圖改由 ChatGPT Image Generation 產生，Kling 只負責 O3 影片。先前生成的圖片保留為歷史紀錄，不再作正式輸入。

這一段用來教三件事：

1. Agent 的第一次決定可能不符合導演的製作方法。
2. 使用者應修正「工作規則」，不只修正眼前的一張圖。
3. 舊結果應保留為歷史紀錄，避免之後誤用或重複花費。

### 7. 將高成本動作放在核准之後

主案例有兩個不同的核准點：

1. **參考圖核准**：確認角色、構圖、鏡位與視覺方向。
2. **影片提交核准**：確認正式參考圖、影片提示詞、模型與生成參數，允許建立一次付費任務。

送片前摘要至少包含：

- 實際模型與版本。
- 每張輸入圖的用途。
- 最終影片提示詞。
- 比例、秒數、解析度與版本數。
- 是否使用多鏡頭與同步音訊。
- 預期成本或點數上限。
- 這次核准允許提交幾次。

### 8. 用任務紀錄避免重複提交

提交完成後，Agent 保存：

- `generationId`
- `taskTraceId`
- `creditsConsumed`
- 任務狀態
- 影片與封面網址
- 建立與完成時間
- 使用的素材、提示詞和參數

查詢期間只追蹤同一個 `generationId`。`QUEUING` 或 `RUNNING` 不代表失敗，也不是再次提交的理由。

### 9. 工具成功不等於作品完成

`COMPLETED` 只代表生成服務完成任務。導演仍需檢查：

| 驗收項目 | 可觀察的問題 |
| --- | --- |
| 角色一致性 | 臉部、髮型、服裝、身形是否保持 |
| 表演 | 是否清楚完成低頭到抬頭的動作 |
| 廣角與機位 | 是否有貼地低機位與近距離廣角的透視感 |
| 攝影機 | 是否只做一次平順的緩慢前推 |
| 物理動態 | 頭髮、衣料與銀飾是否自然且不搶主動作 |
| 光線與色彩 | 夜間直閃、暖窗光與深灰色盤是否成立 |
| 聲音 | 城市底噪與金屬輕響是否符合畫面 |
| 結尾 | 最後一幀是否仍可使用，沒有角色或構圖崩壞 |

下一版修改應寫成：

```text
保留：角色、服裝、場景、光線與抬頭動作。
修改：攝影機前推速度降低一半。
通過條件：人物比例不再明顯改變，最後一秒臉部仍保持清楚。
```

## 八、學員案例的帶領方式

每個案例控制在五分鐘左右，沿用主案例的六個問題：

1. 當時真正想完成什麼？

- 付費或發布前沒有核准點。
- 只有生成結果，沒有驗收與版本紀錄。

## 十二、課程完成條件

這堂課完成時，學員應看過並能口頭重建以下閉環：

```text
一句高階創意
→ 讀取既有 Comfy 提示詞並辨認可沿用的創意結構
→ Agent 讀規則與素材
→ Agent 補齊並說明技術決策
→ 導演核准參考圖方案
→ ChatGPT 產生參考圖
→ 導演核准付費送片
→ Agent 透過 Kling MCP 提交並追蹤同一任務
→ 導演依可觀察標準驗收
→ Agent 根據回饋只改一個主要變因
→ 將可重用方法保存成 Skill
```

最後的檢查題不是「學員能不能寫出同一段英文提示詞」，而是：

> 換一個角色、商品或模型後，學員能不能用高階語言讓 Agent 重新研究、提出方案、執行、驗收並留下可重跑的工作流？
